交易系统逻辑文档

版本：2026-09-20 | 适用于 trading-system-core 项目

本文档描述系统的整体架构、数据流、核心引擎规则、选股评分逻辑、风控体系和配置参数。系统基于白线/黄线趋势框架、MACD 指标、活跃市值百分比和多种战法信号，实现从市场状态判定到选股、风控、仓位管理的完整交易决策链路。

2. 数据源与输入层

活跃市值百分比

  • 来源：Compass 面板导出的 data/compass_active_market_value.csv
  • 读取逻辑：取文件最后一行的 active_market_value_pct 字段
  • 近3日值：用于3日累计多头判定
  • 回退默认值：4.82%（文件不存在或读取失败时）

实时行情

  • 优先读取今日缓存 data/a_spot_latest.csv（每日脚本校验修改日期是否为交易日）
  • 三级降级：ak.stock_zh_a_spot() → ak.stock_zh_a_spot_em() → ak.stock_info_a_code_name()

历史日线

  • 三级重试：ak.stock_zh_a_hist() → ak.stock_zh_a_hist_tx() → ak.stock_zh_a_daily()
  • 前缀规则：6开头→sh，0/3开头→sz，4/8/9开头→bj
  • 前复权（qfq），180天历史数据

股票池过滤

  • 排除300开头（创业板）、688开头（科创板）、ST/退市、无成交
  • 北交所股票（920/8开头）在回测中被过滤

3. 市场状态判定引擎

市场状态是系统的"仓位控制阀"和"进攻信号过滤器"，由活跃市值百分比和MACD综合判定为5档：

状态判定条件最大仓位单标的仓位标签
牛市 BULL 活跃市值 ≥ 4.0% 且 MACD DIF > 0
或3日累计 ≥ 4.0% 且 MACD DIF > 0		 80%20%
震荡偏强 活跃市值 ≥ 1.0% 50%12%
震荡中性 -0.5% < 活跃市值 < 1.0% 35%8%
震荡偏弱 活跃市值 ≤ -0.5% 20%5%
熊市 BEAR 活跃市值 ≤ -2.3% 10%3%

核心作用：市场状态不改变选股池大小，但影响①入场信号评分（弱市扣分）②预筛条件（弱市选抗跌股）③交易计划动作和仓位④B2买点仅允许在牛市和震荡偏强⑤信号环境过滤（弱市仅允许特定信号）。

手动覆盖

支持 --market-override 参数强制指定状态，跳过自动判定。可选值：bull / neutral_strong / neutral_balanced / neutral_weak / bear。

4. 入场信号引擎

4个核心战法

战法条件标签基础分
B1买点 KDJ的J值 < 15 且 知行趋势达标（close > 知行多空线 且 知行趋势线 > 知行多空线） B1/B2买点20
B2买点 B1后1-5日内，涨幅 > 4%，放量，J < 55，趋势达标，无长上影
仅牛市和震荡偏强允许		 B1/B2买点20
单针战法 四周期RSI均 ≤ 6，或短期RSI ≤ 20 且长期 ≥ 70，或短期上穿长期/中期 单针战法15
砖形图反红 自定义砖形图指标出现反转信号 砖形图20

5个辅助信号（技术信号，非战法）

信号条件选股加分
缩量反弹过去5日至少3天缩量、今日放量、上涨且趋势达标仅观察标签，不加分
放量长阳实体涨幅 > 3%，量比前5日均 > 1.5倍，上影线 < 30%+12
锤头线下影线 > 实体2倍，上影线 < 实体0.5倍，创近5日新低+10
回踩白线前1-2日低点回踩白线，今日站上白线并上涨+14
突破压力昨日 < 近20日最高压力位，今日收盘突破并放量+13

信号组合加分

当多个信号同时出现时，按 rulebook.json 的 combo_bonus 配置加分，例如：

  • B1买点 + 回踩白线 → +18
  • B1买点 + 缩量反弹 → +18
  • B1买点 + 放量长阳 → +15
  • 砖形图 + 双线/白黄线 → +10
  • ... 共12种组合

5. 风控引擎

8条风控规则按 risk_priority 配置的优先级排序，数字越小优先级越高。同时触发多条时，取最高优先级的动作。

优先级规则触发条件动作
1盈转亏持仓从盈利转为亏损减仓观察
2初始止损收盘价 < 支撑价（近20日最低价）止损清仓
3S1/卖点命中S1标签 且 当日跌幅 < -2%减仓
4滴滴战法收盘价 < 前一日最低价
白线之上→减仓观察（可留1/2仓位）
白线之下→止损离场		减仓/止损
5破白线收盘价 < 白线（知行趋势线）减仓
6破黄线收盘价 < 黄线（知行多空线）清仓
7MACD否决MACD DIF < 0 且 DIF < DEA否决开仓
8放飞/止盈价格 ≥ 压力位止盈提示

滴滴战法是分级止损策略：白线之上跌破前低→减仓观察（可留半仓）；白线之下跌破前低→止损离场。选股端的"滴滴战法"已改名为"缩量反弹"，仅作观察标签，不参与评分。

6. 交易计划引擎

TradePlanEngine.build_plan() 是最终决策合成器，流程如下：

1. MarketTimingEngine.evaluate()  → 市场状态 MarketState
2. EntrySignalEngine.evaluate()  → 入场信号列表 [Signal]
3. RiskEngine.evaluate()        → 风控动作列表 [RiskAction]
4. 按 allowed_signals 过滤信号（弱市仅允许特定信号）
5. 取最高信号分数 vs pass_score 比较
6. 按优先级输出 TradePlan

决策矩阵

条件动作仓位
有清仓/退出/否决级风控清仓/退出0%
有减仓级风控减仓单标的仓位÷2
熊市观察/不开新仓0%
震荡偏弱 + 信号达标观察/仅B1轻仓单标的5%
震荡偏弱 + 信号不足观察/不开新仓0%
震荡中性 + 信号达标可纳入买入候选单标的8%
震荡中性 + 有信号但不足观察等待确认单标的4%
震荡中性 + 无信号无操作0%
牛市/偏强 + 信号达标可纳入买入候选单标的12-20%
牛市/偏强 + 有信号不足观察等待确认单标的÷2
牛市/偏强 + 无信号无操作0%

7. 指标公式体系

核心趋势线

指标计算方式用途
白线（知行趋势线 zxdq）两层 EWM(10)：EMA(EMA(close, 10), 10)短期趋势判断、破白线风控
黄线（知行多空线 zxdkx）MA(14)、MA(28)、MA(57)、MA(114) 的平均中长期趋势判断、破黄线清仓
BBI(MA3 + MA6 + MA12 + MA24) / 4多空判断
MA6060日均线中长期支撑
知行趋势达标close > zxdkx 且 zxdq > zxdkxB1/B2买点前置条件

支撑与压力

  • 支撑价 = 近20日最低价
  • 压力价 = 近20日最高价
  • 距压力位 ≥ 2% 时加分

MACD

  • DIF = EMA(12) - EMA(26)
  • DEA = EMA(DIF, 9)
  • 多头判定：DIF > 0（零轴上方）
  • 否决条件：DIF < 0 且 DIF < DEA（死叉且零轴下）

10. 选股流程

每日选股（screen_daily_candidates.py）

1. 读取活跃市值 CSV
2. 加载 Rulebook + TradePlanEngine
3. 评估市场状态 → market_regime
4. 加载实时行情 → 过滤股票池
5. 预筛（prefilter_for_history）
   ├ 弱市：成交额≥5000万，涨跌幅-3%~+5%，选抗跌股
   ├ 中性：成交额≥5000万，涨跌幅-1%~+7%，放宽要求
   └ 偏强：成交额≥5000万，涨跌幅0%~+8.8%，选上涨股
   → 按成交额45%+涨跌幅30%+位置25%评分，取前220只
6. 加载板块数据
7. 线程池并发处理（10线程）：
   fetch_daily → build_snapshot → build_plan → evaluate_chart_quality → score_candidate
8. 过滤低于及格线的股票
9. 排序取 Top30
10. 输出 CSV + HTML + JSON
11. 保存历史备份到 outputs/history/
12. 写入 SQLite 数据库
13. Agent 审核（可选）

周一选股（screen_next_monday_candidates.py）

与每日选股流程基本一致，区别：

  • 无板块强度加分
  • 无 Agent 审核
  • 无 SQLite 持久化
  • 支持 --market-override 手动覆盖市场状态
  • 同时输出 daily_candidates.* 和 next_monday_candidates.* 兼容文件

模拟交易规则

  • 全买模式：每只入选股票各买1万元，排除"无操作/不开新仓"的股票
  • 买入价：选股日次日开盘价（含滑点）
  • 卖出价：信号触发日当日收盘价（含滑点）
  • 交易费用：佣金万2.5、印花税千0.5

附录：每日一键执行流程

执行顺序：刷新市场数据 → 检查持仓（生成卖出建议） → 复盘昨日候选 → 生成今日候选 → 运行模拟交易

运行约束：5-8分钟运行时间，按钮禁用，实时进度显示

持仓模块：独立运行，不集成到一键执行流程中

附录：Web面板布局
